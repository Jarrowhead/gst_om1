# AI Build Playbook

> **Status:** v1.0 (2026-09-26) · Owner doc for HOW the build is executed: agent roles, rules, review gates, environment
> **Premise:** the team writes no code. AI agents build everything; humans review outputs and click run. Therefore the process must make AI failure visible and cheap to catch — that is this doc's whole purpose.

---

## 1. Build model — 3-agent pattern (per task)

| Role | Model class | Job | Output |
|---|---|---|---|
| **Writer** | best-coding | Implements ONE task from the plan: code + tests, following the canonical docs exactly | Working code + green tests |
| **Auditor** | pro-reasoning | Reviews the diff against the docs (API shapes, guard rules, paise, locks) BEFORE it merges; writes findings; never edits code | Pass / findings list |
| **Supervisor** | smart | Splits phases into tasks with exact doc references; verifies each task's exit criteria against live output (runs tests, curls endpoints); the ONLY role allowed to declare "done" | Verified task report |

Rules: disjoint ownership (Writer never audits its own task); probe routing shape before big batches (dispatch one small task first and inspect the result quality before mass-dispatching); a task failing audit twice goes back to the Supervisor for re-planning, not a third blind retry.

## 2. Standing rules for every agent (injected into every task context)

| # | Rule |
|---|---|
| 1 | The 8 canonical docs in `docs/` are the contract. If code and doc disagree, fix whichever is wrong — and say which |
| 2 | Never fabricate GSTINs/PANs/invoices. Synthetic fixture GSTINs must be generated by the checksum-valid helper |
| 3 | Money is paise (int) everywhere. No float crosses any boundary |
| 4 | Every registration-scoped route goes through the access guard dependency (API_SPEC non-negotiable #1) |
| 5 | Locked periods return 423; originals are never edited post-filing — amendments are deltas |
| 6 | No test numbers in claims: "done" = tests ran and passed, with counts and names in the report |
| 7 | Python: ruff + mypy clean; TS: eslint + tsc clean — lint failures block a task |
| 8 | Never `pip install` at runtime or commit generated files; declare deps in pyproject/package.json |
| 9 | One task = one module area; never cross-touch files outside the task's stated scope |
| 10 | If a doc is ambiguous, STOP and surface the ambiguity to the Supervisor — guessing inside the GST domain is a compliance bug |

## 4. Task template (Supervisor issues; Writer receives)

```
TASK: <name>
DOCS: docs/API_SPECIFICATION.md §<n>, docs/SECURITY_AND_ACCESS.md §<n>
SCOPE: files the Writer may create/modify (exact paths)
DONE WHEN: executable acceptance (test names + commands + expected result)
OUT OF SCOPE: anything else — touching it fails audit
```

## 5. Review gates (per task)

| Gate | Who | Blocks on |
|---|---|---|
| G-A diff audit | Auditor | doc-contract violations, missing tests, scope creep, paise/float, guard bypass |
| G-B test execution | Supervisor | tests actually run + pass (counts in report); lint/type clean |
| G-C integration smoke | Supervisor (phase exit) | compose stack boots; seeded journey runs end-to-end |

## 7. Failure protocol

| Situation | Action |
|---|---|
| Task fails audit twice | Supervisor re-plans the task; no third blind retry |
| 2+ fix attempts fail without root cause | STOP. Structured analysis at data level (DB, logs, config) before any more edits |
| CI red on main | Build stops; no new tasks dispatched until green |
| Doc-code drift found | Fix the wrong side, bump doc minor version, log in docs/README changelog |
| Golden gate (G1–G3) regresses | Auto-confirm thresholds tighten (or auto-confirm disabled) — accuracy recovers by adding review, never by lowering the bar |
