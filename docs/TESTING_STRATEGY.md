## 1. The pyramid

| Layer | Tool | Scope | Speed | Runs |
|---|---|---|---|---|
| L1 Unit | pytest | pure logic: GstCalculator port, GSTIN checksum, PAN cross-check, fp derivation, classification (B2B/B2CL/B2CS/CDNR/EXP), 2B matching, deadline engine | ms | every commit |
| L2 Integration | pytest + Testcontainers (Postgres) + fakeredis + real MinIO (CI service) | API routes with DB: auth flows, guard matrix, linking lifecycle, lock rules, export generation, 2B import | s | every commit |
| L3 Contract | pinned GSTR-1 offline-utility schema + generated fixtures | JSON generator output validates against schema; golden calculator vectors cross-checked vs Java reference test cases | s | every commit |
| L4 Extraction gates | `scripts/measure_extraction.py` | G1/G2/G3 over golden set | min | CI job (grows with golden set) |
| L5 E2E | Playwright (web) against composed stack | full journeys, both roles | min | every PR + nightly |
| L6 Manual QA | phase-exit checklist (§5) | UX, real-photo edge cases, portal upload dry-run | human | phase exits |

## 2. CI pipeline (GitHub Actions)

| Job | Steps | Blocking? |
|---|---|---|
| `backend` | ruff + mypy (strict on `app/gst`, `app/returns`) → pytest L1/L2/L3 | yes |
| `frontend` | eslint + tsc → next build → unit tests | yes |

| `deps-audit` | pip-audit + npm audit | warn → hard at phase exit |

## 3. Test design rules (AI builders read this as law)

| # | Rule |
|---|---|
| 1 | Table-driven tests for all tax math: intra/inter × rates {0,5,12,18,28} × rounding edges — vectors ported from the Java `GstCalculator` reference suite |
| 2 | Every SECURITY_AND_ACCESS.md §7 test has an integration test; cross-tenant matrix is parameterized, not hand-copied |
| 3 | No test asserts on absolute timestamps — only on ordering/relative offsets |
| 4 | Fixtures: real-format anonymized data only; GSTINs in fixtures are synthetic-but-checksum-valid, generated by a fixture helper (never hand-typed) |
| 5 | Integration tests hit the real guard — no `as_user` bypass helpers that skip authorization |
| 6 | Locked-period behavior is tested by mutation attempt, not by asserting a flag |
| 7 | The GSTR-1 generator has a "known-good full return" golden file (all sections populated) — byte-stable under regeneration |
| 8 | 2B reconciliation: synthetic purchase register + 2B fixtures covering all 5 match statuses, including the fuzzy PROBABLE case |
| 9 | Any bug fixed ⇒ regression test first, then fix (RED→GREEN) |
| 10 | E2E never sleeps arbitrarily — polls API state with timeout |

## 4. Gate wiring

| Gate | Command | Threshold | Enforced |
|---|---|---|---|
| G1 precision | `python scripts/measure_extraction.py …` | ≥ 0.90 mandatory precision | CI `extraction-gates` (hard once golden set ≥ 20) |
| G2 recall | same | ≥ 0.95 mandatory recall | same |
| G3 auto-confirm | same | ≥ 0.99 on auto-confirm subset | same |
| Schema contract | pytest L3 | 100% pass, zero schema violations | every commit |
| Ledger accuracy E2E | L5 suite | ≥ 0.995 post-review accuracy on golden set | phase 2 exit + nightly |
| Coverage floor | pytest `--cov=app` | ≥ 80% on gst/returns/itc modules | warn now → hard at phase 2 exit |

## 5. Per-phase Definition of Done

| Phase | DoD (all verified, not claimed) |
|---|---|
| 0 | Migrations up/down/up clean; auth E2E (both roles, TOTP enforced); CI fully green including compose boot; docs §1–§6 verified against live code |
| 1 | Photo-burst→ledger E2E; linking flows A+B E2E; bulk import error report exact; sandbox IRN generated; guard matrix 100% pass |
| 2 | GSTR-1 golden byte-stable + schema pass; 3B build matches hand-computed fixture; ITC report matches manual CA reconciliation on test client; G1/G2/G3 pass on golden set (≥20 docs); deadline engine notifications fire on schedule |
| 3 | 5-client month-end timed E2E < 30 min; DPDP export/erasure demo; retention job processes; audit UI shows complete trail |
| 4 | Sandbox GSP filing E2E; live IRP gated behind real credentials |

## 6. Manual QA checklist (phase exits)

| # | Check |
|---|---|
| 1 | Real WhatsApp photo (compressed, rotated) uploads and extracts or fails with a helpful message — never garbage data |
| 2 | Blurry photo is rejected with re-upload prompt |
| 3 | CA cannot see ANY data for an unlinked GSTIN via search or direct URL |
| 4 | Exported JSON opens in the official offline utility without errors (test GSTIN account when available; until then, schema validation only) |
| 5 | Revoked CA loses access on next request (no cache staleness) |
| 6 | Locked period: UI blocks edits with clear messaging; GSTR-1A path works |
| 7 | Paise formatting: no float artifacts anywhere in UI or JSON |
| 8 | Deadline countdowns correct across month/QRMP/category-II state edge cases |
